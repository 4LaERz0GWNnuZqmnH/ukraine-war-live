How this site was built

Ukraine War Live is an automated, serverless OSINT aggregator modelled on iranwarlive.com. It has no back-end server and no database in the usual sense. Everything runs on Cloudflare's edge platform, on free tiers, for a running cost of about $0–1 per month. This page describes the whole system in detail — enough to rebuild it.

3. The ingestion pipeline, step by step

Two ingest Workers share one code path (shared/pipeline.ts), parameterised by a PIPELINE variable of strikes or ground. Each fires on its own cron — strikes on the hour every 2 hours, ground 30 minutes later — so they never write KV at the same time.

  1. Fetch feeds. All feeds for this pipeline are fetched concurrently with Promise.allSettled. A feed that errors is recorded and skipped; it never fails the run. Cloudflare edge-caches each response for 5 minutes.
  2. Parse. Workers have no XML DOM, so a small regex parser pulls title, link, publish date and a short summary from RSS and Atom items alike.
  3. Age filter. Items older than 96 hours (4 days) are dropped. The rest are sorted newest-first.
  4. Drop seen URLs. A hash of every processed link is kept in the KV key processed_urls (30-day TTL, pruned each run). Up to 90 unseen items proceed.
  5. AI extraction. The unseen items are sent as a JSON array to Llama 3.3 70B at temperature 0.1 with a strict system prompt. The model is told to emit only a JSON array, to copy the exact source_url of the item an event came from, and to never guess coordinates. Output is capped at 20 strike events / 12 ground events per run.
  6. Validate. Every object is checked: known event type, a real http(s) URL, a valid confidence tier, coordinates inside a Ukraine + western-Russia bounding box (else nulled). Anything malformed is discarded rather than shown.
  7. Geocode fallback. For events the model left without coordinates, a static gazetteer of ~110 places (all oblast centres, front-line towns, Russian refinery/airfield cities) fills in a settlement-centroid position. No geocoding API call.
  8. Cross-run dedup. Each surviving event gets two signatures: a URL hash, and type + 0.5° grid cell + time bucket (1-hour buckets for strikes, 4-hour for territorial change). If either signature is already in the KV key dedup_store, the event is dropped; otherwise its signatures are added.
  9. Archive. Kept events are appended as NDJSON — one JSON object per line — to archive:YYYY-MM-DD, and a date → count map at archive:index is updated.
  10. Live cache. The newest 200 events for this pipeline are written to live:strikes / live:ground. That is what the map reads.
  11. Bookkeeping. A one-line run record (feeds OK/failed, items, fresh, extracted, kept, any errors) goes to status:* and a rolling runs_log.

Every event carries exactly one tier, which is the marker colour on the map.

5. The front-line layer

A third Worker, uwl-ingest-frontline, runs every 6 hours. It fetches deepstatemap.live/api/history/last — a ~600 KB GeoJSON of the current control map — and keeps only the polygons whose status is occupied, plus Crimea and the pre-2022 ORDLO areas. DeepState's satirical "territories" (Karelia, Ichkeria, and so on) and the liberated/dismissed polygons are filtered out. The trimmed FeatureCollection is stored at frontline:geojson and served, heavily cached, from /frontline.json. The map draws it as a semi-transparent red fill beneath the event markers. Front-line data is © DeepStateMap.live, CC BY-NC-SA 4.0.

7. The read API

uwl-api is a fourth Worker on api.ukraine.bugg.club. It has the KV binding and does no writes. The ingest Workers have no public URL at all; the API Worker invokes them for manual runs over a service binding (Worker-to-Worker, no internet hop).

8. The frontend

Plain HTML, one CSS file, one JS file — no framework, no build step. MapLibre GL and its stylesheet load from a CDN; the base map is OpenFreeMap's key-less "Liberty" style. The script fetches /feed.json and /frontline.json, plots markers coloured by confidence tier, and offers time-window and per-type filters plus an occupied-area toggle. The map is treated as progressive enhancement: if WebGL or the tile server is unavailable, the sidebar — counts, per-type tally, and a list of events with no mapped location — still renders. The feed refreshes every 5 minutes client-side; the data itself changes every 2 hours.

9. Hosting and DNS

  • ukraine.bugg.club → Cloudflare Pages custom domain (CNAME to the *.pages.dev project).
  • api.ukraine.bugg.club → a Workers custom domain on the uwl-api Worker (Cloudflare manages the record and cert).
  • The ingest Workers publish to no hostname; they exist only as cron jobs and service-binding targets.

11. Deployment

Each Worker is a wrangler.toml plus a src/index.ts. Secrets (the manual-run key) are set once with wrangler secret put and survive redeploys. A GitHub Actions workflow runs a type-check and then wrangler deploy for each Worker and wrangler pages deploy for the site on every push to main. Cron schedules are declared in the Worker configs and registered automatically on deploy.

12. What this approach gets wrong

  • Headline-only extraction hallucinates. The model can misplace, merge, mis-time, or mis-attribute an event. Temperature 0.1, hard caps, schema validation, the "never invent URLs/coords" instruction and outlet-based tier enforcement reduce it; they do not remove it.
  • Geolocation is coarse. A gazetteer centroid is a town, not a street. Events at places not in the table stay unmapped and are listed in the sidebar instead.
  • Deduplication is lossy both ways. It can drop a genuinely distinct event that shares a grid cell and hour, and it can keep two write-ups of the same strike that describe it differently.
  • Coverage follows the feeds. If an event is not in one of the ~13 RSS sources within 4 days, it does not exist here. Google News RSS, a big potential source, blocks Cloudflare's egress IPs, so it was dropped.
  • Casualty figures are one side's announced numbers (Ukraine's or Russia's), passed through unverified — shown with who reported them and when, and never added into a headline total.
  • The front line lags. DeepStateMap updates a few times a day and this site re-pulls every 6 hours, so the red area can be up to several hours stale.
